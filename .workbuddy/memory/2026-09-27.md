### 返工：摘要行「提升前」分数被判为不对（跨配置混用）

- 根因：`visibleAgentGroups` 里 `score_configuration`（最佳 index）与 `uplift_configuration`（最佳 uplift）**常常是不同模型/智能度的两条配置**。首版摘要行把组级 index 与组级 uplift 的基线直接并排，读起来像「52.02 → 65.99」，实际 52.02+5.56=57.58；Codex 更离谱：index 61.65 的配置真实提升是 −3.54，行里却显示 +3.03。
- 修法（不是改数据，是改呈现）：`agentGroupSummaryMetrics(group, agentName)` 拆成两块 `agentGroupMetricBlock(label, valueNode, context)`——`Coding Agent Index <分> ↗ <模型 · 智能度>` 与 `Terminal-Bench 4.0 提升前 TB4 x ↗ → 提升后 TB4 y ↗ 提升 ±Δ <模型 · 智能度>`；每项都带 `agentConfigurationContext()` 归因到自己的配置，提升前后成对出现且可加减核对。新增 `agentConfigurationContext` / `agentGroupMetricBlock` 两个小函数，删掉 `best` 参数（不再需要）。
- 教训：**组级「最佳值」聚合后不能把不同来源的数字并排展示**，必须要么同源要么逐项归因；新增 `.agent-group-metric / -metric-context / -uplift-pair` CSS。
- 测试：fixture 补 `aa_terminal_bench_v4`；新增 `test_agent_group_summary_tags_each_metric_with_its_own_configuration`（index 与 uplift 故意放在两个不同模型上，断言两个模型名都出现、提升前/后可核对）。全量 293 通过（skip 5）。

## 原始地址记录 + 刷新 + 统一坐标系（model_dashboard）

- 需求原文：「原始地址记录，支持刷新更新；增加统一坐标系对应 token，来衡量性价比」。两项都落地。
- **统一坐标系**：费用快照页最前面新增第四区块 `PRICING_SECTIONS` 的 `key:"value"`（id `section-pricing-value`，hash `pricing-value`，index "00"，label 统一坐标系）。主坐标 `¥/百万 token` = `price_cny_month * 1e6 / included_tokens`，副坐标 `¥/USD` = `price_cny_month / included_usd_credit`。**两者不互相换算**，只公布美元额度的档位记 `—`，区块底部汇总「不做估算」档位数。排序按 `¥/Mtok` 升序 + 相对最优倍数，最优行加 `tr.is-best`。前端 `planCnyPerMtok` / `planCnyPerUsdCredit` / `valueOverview` 与后端 `pricing.value_overview` 同口径。
- 关键决策：**拒绝把「美元额度」硬折算成 token**（无官方依据会产生错误结论）；MiMo 用「1 Credit = 1 Token」最优口径后 ¥0.0080，比 Z.ai ¥0.28 便宜 35 倍，容易误读，故给 MiMo 加 `calibration_note`（社区实测约 30 Credits/token），并在卡片上原样展示。

- 刷新语义：内容指纹 = 归一化空白后 sha256 前 16 位；**指纹不变不推进 `snapshot_at`**，避免把「抓到页面」当成「价格已更新」。

- **坑 1（严重）**：`refresh_pricing_sources` 里 `item["sources"] = source_records(item)` 写在 for 循环之后，而 `source_records()` **每次返回新建的临时字典**，循环内 `record.update(...)` 全落空——表现为「首次 updated=2，第二次仍 updated=2」。修法：循环前先 `records = source_records(item); item["sources"] = records`，再遍历同一批引用。
- **坑 2**：本机会话 `HTTPS_PROXY=http://127.0.0.1:57826` tunnelling 失败（502），`check_source` 直连必然失败。已改为 opener 双阶段：默认 opener（走代理）失败/5xx 时回退 `ProxyHandler({})` 直连，4xx 不再回退。新增 `_DEFAULT_OPENER` / `_DIRECT_OPENER` 两个模块级 opener 便于打桩测试。
- **坑 3**：测试里假 opener 写成 `def open(self, _request, _timeout=None)`，而代码是 `opener.open(request, timeout=timeout)` 关键字传参 → TypeError「unexpected keyword argument 'timeout'」，打桩静默失效，表现为 status=error。假 opener/response 一律用 `(*_args, **_kwargs)`。
- **坑 4**：HTML 断言不能写 `class="source-row"`（前端用 `el(tag, className)` 运行时设 `className`，源码里没有字面量），要断言 `el("div", "source-row")`；同理 `last_checked_at` 与 `checked_at` 是两次抓取的时间戳，只能比到日期，不能比等。
