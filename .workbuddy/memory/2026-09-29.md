## 缓存同步提示优化（文案/信息结构 + 交互行为）

需求原文：「优化缓存同步提示」。先列出现有 4 个触点（顶部提示条、更多→缓存状态、同步 toast、后端 `cache_status()` 的 reason），再确认范围＝**文案与信息结构 + 交互行为**（**不改**后端 reason 字段，`tests/test_data_cache.py` 的断言原样保留）。

**静态审查发现的既有缺陷**（都已修）：① 提示条头部「当前展示的是缓存数据：A、B 需要更新」冒号后接动词，语义歧义；② 逐条明细只有「缓存于 … · 原因」，**没有来源名**，多条时无法与头部对应；③ 未建立缓存时 `cached_at` 为 null，`dateTime(null)` 返回「未知」，于是渲染成自相矛盾的「缓存于 未知 · 尚未建立缓存」；④ `#cache-banner` 没有 `role="status"`，动态出现时屏幕阅读器不播报；⑤ 同一动作三套文案（更新 / 立即更新 / 刷新本地结果）。

改动（`model_dashboard/static/index.html`）：

- **文案与信息结构**：头部改「以下数据源的缓存已过期：A、B」+ 副行「页面仍展示缓存数据，可逐项更新，也可一次全部更新。」；按钮统一为「全部更新」/「更新」/失败时「重试」。逐条明细改为 `来源名 | 缓存时间 · 原因 [· 上次更新失败：xxx]`。新增 `cacheSourceDetail()`：无 `cached_at` 时只写 `reason`，不再出现「缓存于 未知」。`#cache-banner` 加 `role="status" aria-live="polite"`。缓存状态列表徽章 stale→「待更新」、新增 `.failed`→「更新失败」。
- **交互行为**：新增模块级 `cacheUpdateState = { busy, notice, failures: Map }`。`runCacheUpdates()` 用 `Promise.allSettled` **并发**更新多来源（原来 `for...of` 串行），总耗时从「逐源相加」压到「最慢一源」；`runAllLeaderboardSyncs()` 同样改并发。单个失败不中断其余，失败来源保留在提示条上并附错误原因 + 「重试」入口，直到该来源被判定为最新（`renderCacheBanner` 里清理非 stale 的 failures）。进行中时 `notice` 显示「正在更新 A、B…」并禁用全部入口。
- **收口**：`updateCacheSource()` / 顶栏 `refresh-local` / 提示条全部走 `runCacheUpdates()` 单一路径；`refresh-local` 也加进 `syncControlButtons()`（此前同步期间不禁用，点击会静默 no-op）。

**并发安全性依据**：服务端是 `ThreadingHTTPServer`，`DashboardStore._mutate` 用 `RLock` + `BEGIN IMMEDIATE`（`timeout=5`）串行化写入，各来源的网络抓取在锁外，因此前端并发既安全又真能省时间。

**测试**：新增 `tests/test_cache_prompt_display.py`（14 例）。沿用仓库切片手法（`source.indexOf("    const cacheUpdateState = {")` → `"    function filteredModels("`），在最小 DOM 桩（`Node` 类 + `document.getElementById` 自动建节点 + `el`/`dateTime` 注入）上跑 `renderCacheBanner()`，断言标题/副行/逐条明细/徽章/失败重试/清理；另有 2 例做源码级约定断言（HTML 上的 `role=status`、`runCacheUpdates` 内必须是 `Promise.allSettled` 且不含 `for (const source of sources)`）。

**回归**：`python3 -m unittest discover -s tests` = **346 通过**（332 基线 + 14 新增，skip 5）；`compileall` OK；`vm.Script` 单 `<script>` 解析 OK；`<style>` 无需动。

**验证通道补充**：截图通道依旧不可用（同上一节结论）。改用 **jsdom**（`/Users/ben/.workbuddy/binaries/node/workspace/node_modules/jsdom`）做 DOM 级验证，效果很好——`import jsdom` 在 `/tmp` 下会 `ERR_MODULE_NOT_FOUND`（ESM 不认 `NODE_PATH`），**脚本必须放在 workspace 目录内**或直接 import 绝对路径。另有坑：jsdom 里对本地服务发 8 个并发 fetch 会 `ECONNRESET`（curl 和单发 node fetch 都正常），做端到端时改成「curl 抓真实 `/api/cache/status` → 注入 jsdom」更稳。真实数据下提示条如期显示 4 个过期来源与「全部更新」。

**下一轮注意事项**：`docs/model-dashboard.md` 的「启动与数据缓存」段已同步更新（并发、失败重试、按钮改名）；改提示条文案时同步维护 `tests/test_cache_prompt_display.py` 里的字符串断言。
